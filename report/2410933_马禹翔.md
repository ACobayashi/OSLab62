## 三、实验整体逻辑

**负责人**　2410933 马禹翔

Lab1 提供内核启动和串口输出，Lab2 提供物理页分配与分页基础，Lab3 提供 Trap 入口和返回。本实验在这些基础上完成页映射、内核线程创建与调度。线程要真正执行，依次需要可用的内存、可被调度器发现的 PCB，以及能恢复的寄存器和栈。

1. `kern_init()` 先进入 `pmm_init()`，建立物理页管理、页表和内核小块分配的基础。页映射模块维护页表项、物理页引用计数和 TLB。完成中断控制与 Trap 初始化后，`vmm_init()` 检查虚拟内存区域的管理结构。
2. `proc_init()` 把现有启动现场包装成 PID 0 的 `idleproc`，沿用启动栈，将它设为 `current` 并置位 `need_resched`。随后用 `kernel_thread()` 创建 PID 1 的 `initproc`。创建过程分配独立内核栈，构造 `trapframe` 和 `context`，登记线程并将其置为 `PROC_RUNNABLE`。此时 init 已就绪，CPU 仍在运行 idle。
3. 时钟和中断启用后，`cpu_idle()` 看到调度请求，调用 `schedule()` 选择 init。随后 `proc_run()` 更新 `current`、加载目标页表并调用 `switch_to()`。`switch_to()` 保存旧寄存器、恢复目标寄存器，并通过恢复出的 `ra` 继续执行。
4. init 的初始 `context.ra` 指向 `forkret`，接着经 `forkrets → __trapret → sret` 恢复预设的 Trap 现场。预设的 `epc` 指向 `kernel_thread_entry`，它从 `s0` 取函数地址、从 `s1` 取参数，最终调用 `init_main`。已运行过的线程被切回时，会从自己此前的切换调用处恢复。

`PROC_RUNNABLE` 涵盖就绪和运行，实际占用 CPU 的线程由 `current` 标识。两条内核线程共享内核页表，`mm` 为 NULL。本次启动靠 idle 主动调度，评分测试中的线程也主动调用调度。完整的时钟抢占、用户地址空间复制和退出回收留待后续实验。

### 4.3 功能模块三：进程调度与上下文切换

**负责人**　2410933 马禹翔

#### 模块功能描述

| 函数 | 输入及约束 | 状态变化与可检查的结果 |
|---|---|---|
| `cpu_idle()` | 启动已完成，`current` 已设置 | 持续读取 `need_resched`，置位时调用调度。函数持续运行，标记由调度器清除。 |
| `schedule()` | `proc_list` 已初始化，当前普通线程位于链表内 | 保存在本核的中断状态并清标记。从 idle 调用时从表头后继开始，从普通线程调用时从自身后继开始。跳过表头和非就绪节点，绕一圈仍无可运行普通线程便选 idle。选中者的 `runs` 加一，再调用 `proc_run()`。 |
| `proc_run(proc)` | 目标 PCB 和内核映射已准备好 | 目标为当前线程时直接返回。否则关闭本核中断、保存旧线程指针、更新 `current`、加载 Sv39 `satp`、刷新 TLB，再切换现场。旧线程恢复后按自己的记录恢复中断。 |
| `switch_to(from, to)` | `a0`、`a1` 分别指向两个有效的 `context` | 保存和恢复 `ra、sp、s0–s11`，字段偏移从 0 至 104 字节，每项 8 字节。恢复 `sp` 后只从目标现场取值，通过 `ret` 跳往目标 `ra`。 |

**SPEC 设计过程。** 一层只承担一个职责，从底层寄存器切换向上确定页表和中断保护、可运行线程选择、空闲时的触发条件。线程创建侧提供新栈和首次返回地址，初始化侧提供 idle、普通进程链表与首次调度请求。汇编偏移逐项对照 `proc.h`，页表编码对照启动汇编。对空链表、绕回当前节点、恢复旧栈三个边界分别设置可观察条件。

**核心理解。** `schedule()` 决定选谁，`proc_run()` 使 PCB、页表和恢复现场一致。上下文切换发生在函数调用边界，调用者负责自身仍需使用的 caller-saved 寄存器。切换例程保存 `ra`、`sp` 和 callee-saved 的 `s0–s11` 即可继续执行。Trap 可以在普通执行流中异步发生，因此 Lab3 的返回现场还需要恢复更多通用寄存器和特权状态。新线程借用 Trap 返回启动，已运行线程沿原调用链恢复。

**验证设计。** 先用目标文件编译和反汇编检查接口及偏移，再观察正式内核进入 init。原评分检查两条测试线程均得到执行，独立副本进一步验证链表边界、切回后的寄存器和中断状态，见 5.3。

### 4.4 扩展分析：中断保存与恢复

**负责人**　2410933 马禹翔

`sync.h` 中的 `local_intr_save(flag)` 把 `__intr_save()` 的结果写入调用者的变量。它读取 `sstatus.SIE`，如果原先开启，就调用 `intr_disable()` 清除该位并返回 1。如果原先关闭，就保持关闭并返回 0。`local_intr_restore(flag)` 只在记录为 1 时调用 `intr_enable()`。`intr.c` 中的两个函数分别清除、设置 `SSTATUS_SIE`。

| 入口状态 | 保存值 | 进入临界区后 | 恢复后的状态 |
|---|---:|---|---|
| SIE=1 | 1 | 关闭 | 开启 |
| SIE=0 | 0 | 关闭 | 保持关闭 |

以原先开中断的 `schedule() → proc_run()` 为例，外层先记下 1 并关中断，内层看到 SIE=0，记下 0。原线程切回后从 `switch_to()` 返回，内层恢复时继续保持关闭，等外层完成才按记录重新开启。原先关闭时，两层记录都为 0。首次运行的新线程经 `sret`，由其 Trap 帧中的 SPIE 决定返回后的 SIE，和旧线程稍后继续执行的恢复路径相互独立。

`schedule()` 保护调度标记、链表遍历和运行计数，`proc_run()` 保护更新 `current`、加载页表和切换寄存器的过程，`do_fork()` 也用相同机制保护线程的资源准备与登记。SIE 只影响本 hart 的 S 模式中断，其他 hart 仍可访问共享数据。多核的共享链表还需要锁等跨核同步机制。

分析依据是宏和两个中断函数的实现。独立测试先检查两层标记的取值，再实际切走并切回，核对初始 SIE 为 0 和 1 时的最终状态。结果见 5.3。

## 六、实验总结与收获

### 对操作系统的理解

**负责人**　2410933 马禹翔

| 实验知识点 | 对应 OS 原理及本次边界 |
|---|---|
| 调度策略与上下文切换 | 调度决定谁获得 CPU，切换机制保存和恢复状态。本实验沿链表轮转找就绪线程，依靠启动时 idle 或测试线程主动触发。时间片抢占和优先级策略属于后续扩展。 |
| PCB、context 与 Trap 帧 | PCB 描述线程状态和资源。`context` 保存函数调用边界上恢复执行所需的寄存器，Trap 帧还保存异常或中断返回所需的特权和寄存器状态。首次运行把两者串起来。 |
| 页表和内核栈 | `satp` 选择地址翻译所用的根页表，`sp` 决定当前执行使用的栈。本次线程共享内核页表，各自使用内核栈。用户态地址空间隔离不是本实验的实现目标。 |
| 中断临界区 | 保存并恢复 SIE 可防止本 hart 被可屏蔽中断打断，也允许保护区嵌套。多核并发还需跨 hart 的互斥和内存顺序约束。 |

完整的进程退出、等待与资源回收是另一个重要缺口。当前线程返回后进入占位 `do_exit()`。实际系统还需要标记退出状态、通知等待者并在安全时机回收栈与 PCB。
