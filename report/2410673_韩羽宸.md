##### 模块功能描述

我负责的四个函数位于 [`kern/process/proc.c`](../code/kern/process/proc.c)。Lab4 先准备物理页与内核映射，初始化 VMA 管理结构，再由 `proc_init()` 将启动时已有的执行流登记为 `idleproc`，并通过 `kernel_thread()` 创建 `initproc`。我的模块把入口函数和参数转换为可被调度的线程：建立 PCB、独立的内核栈和首次运行现场，完成登记后将线程置为 `PROC_RUNNABLE`。调度部分随后选择线程并切换到它的现场。这样，Lab2 的页分配机制给新线程提供内核栈，Lab3 的 Trap 返回机制可以用来恢复人为构造的首次运行现场。

**功能说明与 SPEC**

**SPEC 设计过程**

我先从手册的功能模块二确认四个函数的责任，再对照源码把描述拆成能落在寄存器和字段上的条件。例如，手册要求线程第一次获得 CPU 时调用传入的函数，我就从 `kernel_thread_entry` 的 `move a0, s1` 和 `jalr s0` 推出 `s1` 必须保存参数，`s0` 必须保存函数地址。这两个字段在创建时写入，之后由 `sret` 前的现场恢复取回。[实验手册](../../../lab_book/手册完整版.html) · [`proc.h`](../code/kern/process/proc.h) · [`trap.h`](../code/kern/trap/trap.h) · [`entry.S`](../code/kern/process/entry.S)

接着把「创建成功」写成可验证的顺序。栈与现场准备好后才分配 PID、更新链表和计数，最后再唤醒线程。这样，分配失败只需要按顺序收回已经取得的资源，调度器也只会看到完成初始化的线程。当前 Lab4 的分配接口不会睡眠，我在 `do_fork()` 开始时保存并关闭本地中断，直到创建结束或回滚完成才恢复原状态。这个范围覆盖进程数检查、PID 分配和登记，符合本次单核执行环境。

**核心函数与首次运行过程**

`kernel_thread()` 构造的现场保存了线程的入口和参数，但这个局部变量在创建者的栈上。`copy_thread()` 把它完整复制到子线程 `kstack + KSTACKSIZE - sizeof(struct trapframe)` 处，使创建者返回后子线程仍能使用这份现场。这里的内核栈大小为两个 4 KiB 页，RV64 的 Trap frame 占 36 个 8 字节槽位。按这个布局，栈顶减去 288 字节后仍满足 16 字节对齐。父调用直接收到 `do_fork()` 返回的 PID，子现场里的 `a0 = 0` 是另一套返回约定。实际进入内核线程函数前，`kernel_thread_entry` 会用 `s1` 把函数参数装入 `a0`。

我在这里把两套现场分开看。PCB 中的 `context` 供调度切换使用，保存 `ra`、`sp` 和被调用者保存寄存器。内核栈上的 `trapframe` 保存 Trap 返回需要的完整通用寄存器现场和相关 CSR。第一轮切换恢复 `context` 后，从 `forkret` 开始执行。`forkret` 把 `current->tf` 交给 `forkrets`，后者把栈指向这份现场并跳转到 `__trapret`。`__trapret` 恢复寄存器和 CSR，`sret` 把执行流送到 `epc` 中的 `kernel_thread_entry`。此时 `SPP=1` 使返回进入 S 模式，`SPIE=1` 使返回后打开 S 模式中断。保存的 `SIE` 为零，使 `__trapret` 写回 `sstatus` 之后、尚未恢复完寄存器时不提前开启中断。最后，入口汇编把 `s1` 转成第一个参数并调用 `s0` 指向的函数，完整启动路径中的目标函数是 `init_main`。

`do_fork()` 的错误路径由「资源已经拿到哪一步」决定。PCB 分配失败时直接结束，栈分配失败时进入 `free_proc`，归还 PCB。如果将来 `copy_mm()` 能返回错误，这时内核栈已经分配，便先从 `free_stack` 归还栈，再继续归还 PCB。三条路径都发生在分配 PID 之前，进程表、哈希和计数因此无需撤销。它们和成功路径共用 `out` 恢复调用前的中断状态。尤其在 `proc_init()` 阶段，调用者原本可能关着中断，此时直接执行 `intr_enable()` 会改变启动阶段的状态。

## 六、实验总结与收获

### 对操作系统的理解

**负责人**　2410673 韩羽宸

| 本实验知识点 | 对应 OS 原理及含义 | 本实验中的联系与差异 |
|--------------|-------------------|----------------------|
| PCB、PID 和 `parent` | PCB 记录操作系统用来管理执行实体的状态。PID 是可查找的标识，父子关系可用于管理创建、退出与回收 | Lab4 中内核线程同样用 `proc_struct` 管理，可由 PID 哈希查找，且拥有自己的内核栈。父子关系由 `parent` 建立，本次只用到创建阶段 |
| 私有内核栈与共享内核页表 | 内核栈保存线程在内核态的调用现场。页表描述虚拟地址到物理页的映射 | 两个线程可以使用同一份内核映射，同时用不同的栈保存各自的函数调用与现场。Lab4 内核线程的 `mm` 为 `NULL`，没有独立的用户地址空间 |
| `context`、`trapframe` 和第一次执行 | 调度器恢复线程运行所需的上下文。Trap 返回另外需要原特权级、返回地址及通用寄存器等信息 | Lab3 恢复的是被打断时保存的真实现场。Lab4 提前构造现场，用同一套恢复流程进入从未运行过的线程，把「保存后继续」的机制扩展到了「构造后首次进入」 |
| 创建顺序、回滚与中断保护 | 资源获取和状态发布有先后关系，内核要避免其他执行路径观察到半初始化的对象 | Lab4 在 PCB、栈和现场齐备后才登记并唤醒。失败时回收已取得的资源。本地关中断适用于当前单核环境，多核共享结构通常还需要锁等跨核同步 |

本实验仍有三项重要的 OS 原理没有覆盖。**用户地址空间复制与写时复制**涉及独立页表、页面共享、引用计数和写入时的缺页处理，本次 `copy_mm()` 只对应内核线程的共享情形。**退出、等待和资源回收**决定一个线程停止后，谁来接收退出状态，谁最终释放 PCB 和栈。本次只验证创建失败时的回滚，完整的退出生命周期仍留在后续实验。**抢占式调度与多核同步**需要时钟参与调度决策，并在多个 CPU 之间维护运行状态的一致性。本次的隔离验证覆盖单核下的首次进入。
