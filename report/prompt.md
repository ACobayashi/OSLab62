### [RELY] 上下文信息

工程为 RV64，目标包含 C 压缩指令扩展。与本任务直接相关的实际接口和常量为：

```c
#define CAUSE_ILLEGAL_INSTRUCTION 0x2
#define CAUSE_BREAKPOINT          0x3
#define CAUSE_FAULT_LOAD          0x5

struct trapframe {
    struct pushregs gpr;
    uintptr_t status;
    uintptr_t epc;
    uintptr_t badvaddr;
    uintptr_t cause;
};

void print_trapframe(struct trapframe *tf);
void exception_handler(struct trapframe *tf);
```

`struct pushregs` 保存 32 个通用寄存器槽位。已有 `SAVE_ALL` 将 `sstatus`、`sepc`、`stval`、`scause` 分别保存到帧中的 `status`、`epc`、`badvaddr`、`cause`。`trap_dispatch()` 用 `((intptr_t)tf->cause < 0)` 区分中断和同步异常，再调用相应处理函数。

这里只要求处理本实验中地址可读、长度为 16 或 32 位的内核故障指令。首半字低两位不为 `11` 时按 2 字节处理，为 `11` 时在本受测范围内按 4 字节处理。该简化不是针对任意 48 位以上编码的通用解码。

最终入口恢复由另一位成员负责：它应把更新后的 `tf->epc` 写回 `sepc` 后执行 `sret`。本人 C 函数不直接操作这个 CSR。

以下启动序列针对没有旧断点的新 GDB 会话。若已经连接，应先确认当前停点和断点编号，不盲目重复连接或删除断点。

- 对用户现场截图的解释与后续步骤，不生成伪造截图。

### [SPECIFICATION] 行为规格

**Post-Condition：** 四例实际原因码分别为 2、2、3、3，EPC 增量分别为 4、2、2、4；每例真实返回的 PC 与新 EPC 一致，SP 等于进入前保存值，哨兵寄存器恢复正确。

**Case 1——连接并跳过构造帧：** 终端 A 在个人副本运行 `make debug`。终端 B 执行：

```bash

  codex-lab2-lzy-debug-arm64-01a15ea8 gdb-multiarch -q bin/kernel
```

新 GDB 会话中执行：

```gdb
set pagination off
set logging file manual-gdb.log
set logging enabled on
target remote 127.0.0.1:1234
hbreak lab3_illegal32
continue
delete 1
hbreak exception_handler
continue
```

第一处探针断点用于跳过前面的构造帧调用，不把直接 C 调用算作 CPU 异常。

**Case 2——进入时记录：**

```gdb

set $old_epc = $frame->epc
set $saved_sp = $frame->gpr.sp

p/x $old_epc
x/2xh $old_epc
p/x $sepc
p/x $stval
p/x $saved_sp
```

每次新异常都重新保存这三个变量。通过实际原因码和故障半字确认异常，不以驱动开始行的预期值代替读取。

**Case 3——C 处理后检查：**

```gdb
continue

p/d $frame->epc - $old_epc

```

此时帧 EPC 应已前进，但恢复宏尚未执行，`sepc` 可以仍为旧地址；应解释为两个状态检查点不同，而不是立即判为代码失败。

**Case 4——实际返回检查：**

```gdb
thbreak *$frame->epc
continue
p/x $pc
p/x $sepc
p/x $sp
p/x $saved_sp
info registers t0 a0 s0
```

应停在对应 `resume`，`pc` 与 `sepc` 等于新 EPC，SP 等于保存值，`t0=0x105`、`a0=0x10a`、`s0=0x108`。前三例继续后进入下一例，再重复入口记录；不能拿旧 `$frame` 指向的已复用内容跨例作比较。

**Requirements：** 区分“停在返回标签”和“整个探针已执行完”；后者还需探针断言通过或完整运行结果支持。四例完成后若需要让本次 GDB 运行继续结束，应删除断点、`detach`、`quit`，再确认控制台结果；没有看到的退出操作不能记成已手动完成。
